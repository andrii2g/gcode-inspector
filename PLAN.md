## 0. Project purpose

Create a .NET command-line static analyzer for generated FFF/FDM G-code.

The tool inspects slicer-generated G-code and reports print-risk areas that slicer previews may show visually but do not explain as actionable warnings. The first high-value use case is bridge-risk detection: long unsupported bridge moves generated by PrusaSlicer, OrcaSlicer, Slic3r-style slicers, or any slicer that emits compatible `;TYPE:` comments matching the MVP feature-classification contract. Cura-specific comments and Cura-specific behavior are not part of the MVP unless added later as an explicit contract.

The MVP must answer these questions:

```text
Does this G-code contain long unsupported bridges?
Where are they?
How severe are they?
What local slicer or model changes should I try?
Is there an alternative bridge angle candidate worth trying?
```

## 1. Non-goals for MVP

Do not implement these in the first version:

```text
Full slicer replacement
STL, STEP, 3MF, or mesh reconstruction
G-code rewriting or automatic repair
Interactive UI or 3D viewer
Printer-specific physics simulation
Thermal modeling
Filament-brand-specific recommendations
Exact bead-width reconstruction
Perfect support-area polygon reconstruction
Cura-specific feature-comment classification
```

The MVP is a deterministic static analyzer with intentionally approximate but explainable geometry heuristics.

## 7. CLI contract

### 7.1 Commands

Required commands:

```bash
gcode-inspector analyze <file.gcode>
gcode-inspector analyze <file.gcode> --format json
gcode-inspector analyze <file.gcode> --format markdown --output report.md
gcode-inspector explain BR001
gcode-inspector explain BR002
```

### 7.2 Analyze options

Required positional argument:

```text
file
```

The input file must exist and must be readable.

Options:

```text
--format <text|markdown|json>             Default: text
--output <path>                           Optional. If omitted, write to stdout.
--fail-on <none|warning|critical>         Default: none
--max-bridge-span-warning <mm>            Default: 25
--max-bridge-span-critical <mm>           Default: 50
--support-tolerance-mm <mm>               Default: 0.45
--sample-spacing-mm <mm>                  Default: 1.0
--detect-heuristic-bridges <true|false>   Default: true
--angle-step-degrees <degrees>            Default: 45
--angle-min-improvement-percent <percent> Default: 20
--verbose                                 Default: false
```

Validation:

```text
format must be text, markdown, or json
fail-on must be none, warning, or critical
max-bridge-span-warning must be > 0
max-bridge-span-critical must be >= max-bridge-span-warning
support-tolerance-mm must be > 0
sample-spacing-mm must be > 0
angle-step-degrees must be > 0 and <= 90
angle-min-improvement-percent must be > 0 and < 100
```

### 7.3 Exit code contract

Analysis-success exit codes are controlled only by `--fail-on` and detected severity.

```text
0  = analysis completed and selected fail-on policy was not triggered
1  = analysis completed; --fail-on warning was triggered by at least one warning or critical finding
2  = analysis completed; --fail-on critical was triggered by at least one critical finding
64 = invalid CLI arguments
65 = input file cannot be read
66 = parser failed because the file is malformed beyond recovery
67 = output file cannot be written
70 = unexpected runtime error
```

Explicit matrix for successful analysis:

```text
fail-on=none
  no findings        -> 0
  info only          -> 0
  warnings only      -> 0
  critical findings  -> 0

fail-on=warning
  no findings        -> 0
  info only          -> 0
  warnings only      -> 1
  critical findings  -> 1

fail-on=critical
  no findings        -> 0
  info only          -> 0
  warnings only      -> 0
  critical findings  -> 2
```

Error exit codes `64`, `65`, `66`, `67`, and `70` override `--fail-on`.

The CLI must not crash with an unhandled exception for expected user errors.

## 8. G-code parser contract

The parser must be stateful and modal. Do not require every `G0` or `G1` line to contain `X`, `Y`, `Z`, `E`, and `F`.

### 8.1 Supported commands for MVP

Handle at minimum:

```text
G0, G1
G90, G91
G92
M82, M83
G20, G21
; comments
```

Behavior:

```text
G0/G1 = movement command
G90    = absolute XYZ positioning
G91    = relative XYZ positioning
G92    = set current position for any provided axis; most important: G92 E0
M82    = absolute extrusion mode
M83    = relative extrusion mode
G21    = millimeters; supported no-op
G20    = inches; unsupported for MVP and must produce parser error 66 if movement follows while inch mode is active
```

Unknown commands must be ignored unless they contain malformed numeric tokens for a supported command. Preserve line number and raw text when useful for diagnostics.

### 8.2 Comments

Support both full-line and inline comments:

```gcode
;TYPE:Bridge infill
G1 X10 Y10 E0.45 ; inline comment
```

Parsing rules:

```text
Strip the comment before command-token parsing.
Use the comment part for slicer metadata classification.
Empty lines and comment-only lines are valid.
```

### 8.3 Machine state

Track this modal state:

```text
current X, Y, Z, E
current feed rate F
XYZ positioning mode: absolute or relative
extrusion mode: absolute or relative
unit mode: millimeters or inches
current layer index
current layer Z
pending layer-change comment flag
pending slicer layer index metadata
pending slicer Z metadata
pending layer height metadata
current feature type
current raw feature type text
```

Defaults:

```text
X = 0
Y = 0
Z = 0
E = 0
F = null
XYZ positioning mode = absolute
extrusion mode = absolute
unit mode = millimeters
current layer index = 0 only after first extrusion layer is created
current feature type = unknown
current raw feature type text = null
```

### 8.4 Modal coordinate handling

For `G0` and `G1`:

```text
Missing X means X is unchanged.
Missing Y means Y is unchanged.
Missing Z means Z is unchanged.
Missing E means no extrusion change.
Missing F means feed rate is unchanged.
```

For absolute XYZ mode:

```text
new X = command X if present, otherwise current X
new Y = command Y if present, otherwise current Y
new Z = command Z if present, otherwise current Z
```

For relative XYZ mode:

```text
new X = current X + command X if present, otherwise current X
new Y = current Y + command Y if present, otherwise current Y
new Z = current Z + command Z if present, otherwise current Z
```

For absolute extrusion mode:

```text
extrusionDelta = command E - current E, if E is present
extrusionDelta = 0, if E is missing
current E becomes command E when E is present
```

For relative extrusion mode:

```text
extrusionDelta = command E, if E is present
extrusionDelta = 0, if E is missing
current E becomes current E + command E when E is present
```

For `G92`:

```text
No movement segment is created.
Any provided axis updates current machine state for that axis.
G92 E0 resets current E to 0.
Missing axes are unchanged.
```

### 8.5 Segment classification

A parsed `G0` or `G1` movement creates a `ToolpathSegment` only when XY distance is greater than zero.

Classification:

```text
extrusion segment: XY distance > 0 and extrusionDelta > 0
travel segment:    XY distance > 0 and extrusionDelta <= 0
Z-only movement:   Z changes and XY distance = 0; no ToolpathSegment
E-only movement:   E changes and XY distance = 0; no ToolpathSegment
retraction:        extrusionDelta < 0; no extrusion segment
prime-only move:   extrusionDelta > 0 and XY distance = 0; no ToolpathSegment
```

Feed rate:

```text
If F is present, update current feed rate before storing the segment.
If no F has ever been seen, segment feed rate is null.
```

### 8.6 Layer detection and metadata precedence

Layer detection must support comment-based and Z-based files.

Comment-based markers:

```text
;LAYER_CHANGE
;LAYER:<integer>
;Z:<number>
;HEIGHT:<number>
```

Rules:

```text
A layer is created when the parser sees the first XY extrusion segment.
PrintLayer.ZMm is always the actual machine Z value of the first XY extrusion segment assigned to that layer.
Comment metadata never overrides PrintLayer.ZMm.
If ;LAYER_CHANGE appears, mark a pending layer boundary.
The next XY extrusion segment after a pending layer boundary starts a new layer.
If pending ;LAYER_CHANGE and Z-based detection both apply to the same extrusion segment, create exactly one new layer.
If ;LAYER:<integer> appears, preserve it as pending SlicerLayerIndex metadata for the next extrusion layer; internal LayerIndex remains zero-based and ascending.
If ;Z:<number> appears, preserve it as pending SlicerZMm metadata for the next extrusion layer.
If ;HEIGHT:<number> appears, preserve it as pending HeightMm metadata for the next extrusion layer.
If comment metadata disagrees with actual extrusion Z, keep both values and continue parsing.
All geometry, support sampling, BR001/BR002 evaluation, text output Z, markdown output Z, and JSON zMm must use PrintLayer.ZMm.
Without comments, a new layer starts when an XY extrusion segment occurs at a Z value greater than the previous extrusion layer Z by more than 0.001 mm.
Travel Z-hops do not create new layers unless extrusion resumes at a new higher Z.
If Z rises during travel and returns to the previous layer Z before extrusion, do not create a new layer.
```

Metadata precedence example:

```gcode
;LAYER_CHANGE
;Z:0.40
G1 Z0.42 F1200
G1 X10 Y10 E0.2
```

The created layer must have:

```text
PrintLayer.ZMm = 0.42
PrintLayer.SlicerZMm = 0.40
```

Layer zero:

```text
LayerIndex starts at 0 for the first extrusion layer.
BR001/BR002 must not analyze LayerIndex 0 as unsupported bridge risk because the build plate acts as support.
```

### 8.7 Slicer feature-type comments

Recognize these comments at minimum:

```text
;TYPE:Bridge infill                 -> BridgeInfill
;TYPE:Internal bridge infill        -> InternalBridgeInfill
;TYPE:Overhang perimeter            -> OverhangPerimeter
;TYPE:Internal infill               -> InternalInfill
;TYPE:Solid infill                  -> SolidInfill
;TYPE:Top solid infill              -> TopSolidInfill
;TYPE:Perimeter                     -> Perimeter
;TYPE:External perimeter            -> ExternalPerimeter
;TYPE:Support material              -> SupportMaterial
;TYPE:Support material interface    -> SupportMaterialInterface
```

Matching must be case-insensitive and must trim whitespace.

MVP scope boundary:

```text
Feature classification is limited to the Slic3r/PrusaSlicer/OrcaSlicer-style `;TYPE:` comments listed above.
Do not add Cura-specific comment mappings in the MVP.
Cura-generated G-code may still be parsed as generic modal G-code, but unsupported Cura-specific metadata must fall back to FeatureType.Unknown.
```

Unknown `;TYPE:` values:

```text
Map to FeatureType.Unknown.
Preserve the original text in RawFeatureType.
Do not fail parsing.
```

## 10. Geometry and support sampling

Avoid heavy polygon libraries in the first version. Use segment-distance sampling.

### 10.1 Support detection primitive

For a candidate bridge segment on layer `N`:

```text
Previous material = all extrusion segments from layer N - 1.
If N = 0, skip analysis.
If previous material is empty, the whole candidate span is unsupported.
```

A point is supported when:

```text
distance from point to any previous-layer extrusion segment <= support-tolerance-mm
```

The comparison is inclusive. A point exactly `support-tolerance-mm` away is supported.

### 10.2 Unsupported span calculation

Use interval midpoint sampling, not only endpoint sampling.

Given candidate segment length `L` and configured `sample-spacing-mm`:

```text
step = sample-spacing-mm
Create intervals [0, step], [step, 2*step], ... until L.
The final interval may be shorter than step.
For each interval, sample the midpoint distance along the segment.
The interval is supported if the midpoint is supported.
The interval is unsupported if the midpoint is unsupported.
The longest unsupported span is the maximum total length of consecutive unsupported intervals.
The unsupported-span position is the midpoint of the longest unsupported interval run.
```

If `L < sample-spacing-mm`, create exactly one interval `[0, L]`.

All BR001 threshold comparisons use the unrounded computed span. Output values are rounded to two decimals.

### 10.3 Support coverage calculation

Support coverage for heuristic bridge detection must use the same sampled intervals from section 10.2.

For a candidate segment with length `L`:

```text
supportedLengthMm = sum of interval lengths whose midpoint is supported
unsupportedLengthMm = sum of interval lengths whose midpoint is unsupported
supportCoveragePercent = (supportedLengthMm / L) * 100
unsupportedCoveragePercent = (unsupportedLengthMm / L) * 100
```

Because BR001 candidates are XY extrusion segments, `L` must be greater than zero. If a defensive implementation encounters `L <= 0`, coverage must be treated as 0 and the segment must not emit a BR001 finding.

Contractual details:

```text
Coverage is length-weighted by sampled interval length.
Coverage is not endpoint coverage.
Coverage is not raw midpoint-count coverage.
Coverage is not exact polygon/bead-area coverage in MVP.
The final short interval contributes its actual interval length, not sample-spacing-mm.
Use unrounded supportCoveragePercent for all comparisons.
If previous material is empty, supportedLengthMm = 0 and supportCoveragePercent = 0.
The phrase "below 50 percent" means supportCoveragePercent < 50.0.
A segment with exactly 50.0 percent support coverage is not a heuristic bridge candidate.
```

`SupportSampler` must return a deterministic `SupportSampleResult` containing longest unsupported span, midpoint, supported length, unsupported length, support coverage, and unsupported coverage.

## 11. Rule BR001: Long unsupported bridge

Rule ID: `BR001`  
Title: `Long unsupported bridge`  
Severity: warning or critical

### 11.1 Candidate segments

A segment is a BR001 candidate when it is an extrusion segment on layer `N > 0` and one of these is true:

```text
FeatureType is BridgeInfill
FeatureType is InternalBridgeInfill
```

Or, when `--detect-heuristic-bridges true`, it is also a candidate when all are true:

```text
FeatureType is Unknown, SolidInfill, TopSolidInfill, or InternalInfill
segment length >= max-bridge-span-warning
supportCoveragePercent from section 10.3 is < 50.0
```

Do not use perimeter or external perimeter segments as heuristic bridge candidates in MVP.

### 11.2 Thresholds

Default thresholds:

```text
warning:  unsupported span >= 25 mm
critical: unsupported span >= 50 mm
```

`critical` takes precedence over `warning`.

Threshold comparison is inclusive: `>=`, not `>`.

### 11.3 Finding behavior

For each candidate segment:

```text
Compute SupportSampleResult.
If LongestUnsupportedSpanMm < warning threshold, emit no finding.
If LongestUnsupportedSpanMm >= warning threshold and < critical threshold, emit warning.
If LongestUnsupportedSpanMm >= critical threshold, emit critical.
Emit one BR001 finding per risky segment.
Do not group adjacent bridge segments in MVP.
```

### 11.4 Position contract

The reported position is:

```text
PositionKind = unsupportedSpanMidpoint
Position = XY midpoint of the longest unsupported interval run
```

This is not the segment start point unless the longest unsupported run happens to be centered there.

### 11.5 Required BR001 metrics

Include these metrics in the finding:

```text
segmentLengthMm
supportCoveragePercent
supportedLengthMm
thresholdCriticalMm
thresholdWarningMm
unsupportedCoveragePercent
unsupportedSpanMm
```

All metric values are computed from unrounded doubles and rounded only at report serialization time.

### 11.6 BR001 message and suggestions

Message template:

```text
Layer {LayerIndex} at Z={ZMm:0.##} mm contains a bridge segment with approximately {UnsupportedSpanMm:0.##} mm unsupported span.
```

Suggestions:

```text
Try changing the bridge angle for this region.
Add local support or support enforcers.
Add sacrificial internal walls or ribs to shorten the span.
Reduce bridge speed and verify bridge flow/fan settings.
Consider splitting the model or changing orientation.
```

Do not claim the print will definitely fail.

## 12. Rule BR002: Bridge angle candidate

Rule ID: `BR002`  
Title: `Bridge angle candidate`  
Severity: `info`

BR002 is an MVP rule, but it is advisory. It must not create warning or critical findings. It exists to suggest candidate bridge angles after BR001 has found real bridge risk.

### 12.1 When BR002 runs

BR002 runs only for BR001 findings.

Do not emit BR002 when:

```text
No BR001 finding exists.
The related BR001 unsupported span is 0.
Previous-layer support data is unavailable.
No candidate angle improves the estimated unsupported span enough.
```

### 12.2 Candidate angles

Default candidate angles:

```text
0, 45, 90, 135
```

They are generated from:

```text
0 <= angle < 180
step = --angle-step-degrees
```

Exclude candidate angles whose normalized angular difference from the current segment angle is less than or equal to 10 degrees.

Normalized angular difference:

```text
diff = abs(candidate - current)
normalizedDiff = min(diff, 180 - diff)
```

### 12.3 Estimation algorithm

For each BR001 finding:

```text
1. Use the related bridge segment length L.
2. Use the related BR001 reported Position as the center point.
3. Build a virtual segment of length L through that center point at the candidate angle.
4. Run the same SupportSampler against previous-layer extrusion segments.
5. Compute estimatedUnsupportedSpanMm for the candidate.
6. Compute improvementPercent = ((currentUnsupportedSpanMm - estimatedUnsupportedSpanMm) / currentUnsupportedSpanMm) * 100.
```

### 12.4 Emission threshold

Emit one BR002 finding for a BR001 finding only when the best candidate has:

```text
improvementPercent >= --angle-min-improvement-percent
```

Default minimum improvement: `20%`.

If multiple candidate angles satisfy the threshold, include the best two candidates by shortest estimated unsupported span. Break ties by smaller angle.

### 12.5 BR002 position contract

The reported position is the same as the related BR001 finding:

```text
PositionKind = relatedUnsupportedSpanMidpoint
```

### 12.6 Required BR002 metrics

Include these metrics in the finding:

```text
bestCandidateAngleDegrees
bestEstimatedUnsupportedSpanMm
currentAngleDegrees
currentUnsupportedSpanMm
improvementPercent
```

When two candidate angles are included, store the secondary candidate in evidence text rather than adding array-valued metrics in MVP.

### 12.7 BR002 message and suggestions

Message template:

```text
The current bridge direction is approximately {CurrentAngleDegrees:0.##} degrees. Candidate bridge angle(s) {CandidateAngles} may reduce the estimated unsupported span from {CurrentSpan:0.##} mm to about {BestEstimatedSpan:0.##} mm.
```

Suggestion:

```text
Try the candidate bridge angle in the slicer and inspect the regenerated G-code before printing.
```

Do not say the angle is guaranteed. Use candidate language only.

## 14. Parser error handling

Malformed files must not cause unhandled exceptions.

Parser error cases:

```text
Malformed numeric token on a supported command -> parser error 66 with line number
Unsupported inch-mode movement after G20 -> parser error 66 with line number
Unclosed or unusual comments -> tolerate as plain comments when possible
Unknown commands -> ignore
Empty file -> valid analysis with zero layers, zero segments, zero findings
Comment-only file -> valid analysis with zero layers, zero segments, zero findings
```

Error messages must be concise and include the line number when applicable.

Example:

```text
Parse error at line 42: invalid numeric value for X: "abc".
```

## 23. Known MVP limitations

Document these limitations in README and rule docs:

```text
Support detection is segment-distance based, not polygon/bead-area exact.
Bridge angle candidates are heuristic and must be verified by regenerating and inspecting G-code.
The analyzer depends partly on slicer comments for best results.
Heuristic bridge detection may produce false positives when comments are missing.
Only previous-layer support is considered in MVP.
Arc commands G2/G3 are not interpreted in MVP.
Volumetric extrusion and multi-extruder semantics are not fully modeled in MVP.
```
